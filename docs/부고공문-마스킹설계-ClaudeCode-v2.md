## 0. 이 지시서를 읽는 Claude Code에게

1. 이 문서를 끝까지 읽고 구현 계획을 먼저 직원에게 보여 준 뒤, 승인을 받으면 구현한다.
2. 맥 시제품 코드 묶음(16절)을 받았다면 처음부터 새로 짜지 말고 그 코드에서 시작한다. 묶음 코드는 맥에서 시험을 통과했다. Windows에 맞게 바꿀 곳은 16절에 적었다.
3. **구현과 시험은 가짜 데이터로만 한다.** 실제 공문 원본, 대조표, 검수 화면, 검수 표시 파일은 Claude Code가 열거나 출력하면 안 된다. Claude Code가 읽은 내용은 클라우드(Claude API)로 전송되기 때문이다.
4. 오답 노트(13절)에서 Claude Code가 읽어도 되는 것은 가짜화를 거친 `learn\proposals\requests\*.json`과 `learn\` 아래의 다른 파일뿐이다. `secure\learn\` 아래 파일은 진짜 값이 들어 있으므로 읽지 않는다.
5. 14절의 "단체가 정할 항목"은 직원에게 물어서 `config\policy.yaml`에 기록한다. 답을 받기 전에는 더 많이 가리는 쪽을 기본값으로 둔다.

## 1. 목적

새 부고 관련 공문(무연고 사망자 처리 협조 요청 등)이 오면 고인은 단체 DB에 없는 처음 보는 사람이다. 따라서 미리 가진 명단과 대조하는 방식은 쓸 수 없다. 이 프로그램은 공문을 내려받은 직후 개인정보만 가린 사본을 만들고, Claude는 그 가린 사본만 가공하게 한다.

가릴 항목은 다음 4가지이다.

| 항목 | 치환 표기 | 예(가짜 값) |
|---|---|---|
| 사람 이름 | `[이름1]`, `[이름2]` … | 홍길동 → `[이름1]` |
| 주민등록번호 | `[주민번호]` | 500101-1234567 → `[주민번호]` |
| 전화번호 | `[전화번호]` | 010-1234-5678 → `[전화번호]` |
| 주소 | `[주소]` | 서울특별시 가상구 예시로 12, 101동 202호 → `[주소]` |

핵심 원리는 다음과 같다. 처음 보는 사람이라도 신청서 "이름" 칸에 적힌 글자가 곧 그 사람 이름이다. 그 칸에서 이름을 읽어 두었다가 서류 나머지에서 같은 이름이 나올 때마다 가린다. 칸에 없는 이름은 NER 모델이 찾고, 그래도 놓친 것은 검수에서 표시해 오답 노트로 규칙을 고친다.

## 2. 절대 원칙 — 외부 전송 금지

1. 마스킹 처리 코드는 **로컬 파이썬과 로컬 Node의 kordoc으로만** 동작한다. Claude API, OpenAI API, 클라우드 OCR, 번역 API 등 어떤 원격 서비스도 부르지 않는다. `anthropic`, `openai`, `requests`, `httpx`, `urllib.request` 같은 네트워크 모듈을 `app\` 코드에서 import하지 않는다. 검수 화면은 파이썬 표준 라이브러리 `http.server`로 `127.0.0.1`에만 연다.
2. 원본 공문, 대조표, 검수 화면, 검수 표시는 PC 밖으로 내보내지 않는다. 구글 드라이브·NAS 동기화 폴더 안에 두지 않는다.
3. 프로그램은 실행 중 화면(stdout)과 로그에 **값을 쓰지 않는다.** "3건 처리, 검수 대기 3건, 실패 0건"처럼 건수와 상태만 쓴다. Claude Code가 이 프로그램을 실행하면 출력이 Claude에게 전달되기 때문이다. 오답 노트 명령(`learn.py`)의 출력도 같은 규칙을 따른다.
4. 실행 시작 시 파이썬 네트워크 차단 장치(`app\netguard.py`)를 켠다. `socket.socket.connect`, `socket.create_connection`, `socket.getaddrinfo`를 감싸서 `127.0.0.1`·`localhost`가 아닌 주소로 연결하려 하면 예외를 던지고, 시도 사실(주소만, 값 없음)을 `logs\netguard.log`에 남긴다. 이 로그가 비어 있어야 정상이다.
5. 모델(OCR, NER)은 설치할 때 한 번만 인터넷으로 내려받는다. 이때는 공문을 다루지 않는다. 그 뒤에는 `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, `KORDOC_OFFLINE=1`, `PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK=True`를 설정해 오프라인으로만 실행한다.
6. kordoc을 Node로 실행할 때는 `NODE_OPTIONS=--require C:\nanum-mask\app\netguard.cjs`를 함께 준다. `netguard.cjs`는 `net.Socket.prototype.connect`, `dns.lookup`·`dns.resolve`, `fetch`를 감싸서 외부 연결을 막고 시도를 `logs\netguard.log`에 기록한다.
7. **Windows 방화벽으로 한 번 더 막는다.** 맥에서는 kordoc을 `sandbox-exec`로 실행해 운영체제 수준에서 네트워크를 막았다. Windows에는 이 장치가 없으므로 방화벽 규칙으로 대신한다.
   - 마스킹 전용 Python과 Node를 `C:\nanum-mask\python311\`, `C:\nanum-mask\node\`에 따로 설치한다. PC에 이미 있는 `node.exe`를 막으면 같은 Node로 도는 다른 프로그램(npm으로 설치한 Claude Code 등)도 인터넷을 쓰지 못하기 때문이다.
   - 모델을 내려받고 설치를 마친 뒤, 관리자 PowerShell에서 아래 규칙을 넣는다. 가상환경의 `python.exe`는 기본 Python을 다시 실행하는 실행기이므로 두 파일을 모두 막는다.

```powershell
New-NetFirewallRule -DisplayName "nanum-mask python 외부 차단" -Direction Outbound -Action Block -Program "C:\nanum-mask\python311\python.exe"
New-NetFirewallRule -DisplayName "nanum-mask venv 외부 차단"   -Direction Outbound -Action Block -Program "C:\nanum-mask\.venv\Scripts\python.exe"
New-NetFirewallRule -DisplayName "nanum-mask node 외부 차단"   -Direction Outbound -Action Block -Program "C:\nanum-mask\node\node.exe"
```

   - 규칙을 넣은 뒤 차단 장치 없이 바깥 주소에 연결해 실패하는지 확인한다. `C:\nanum-mask\.venv\Scripts\python.exe -c "import socket; socket.create_connection(('example.com', 443), 5)"`가 오류로 끝나야 정상이다. 그다음 검수 화면(12절)을 열어 `127.0.0.1` 연결은 되는지 확인한다.
   - 모델을 다시 내려받아야 할 때만 규칙을 잠시 끄고(`Disable-NetFirewallRule -DisplayName "nanum-mask*"`), 받은 뒤 바로 다시 켠다(`Enable-NetFirewallRule`). 이때는 공문을 처리하지 않는다.

transformers==5.20.2  torch==2.14.1(CPU판)  numpy==2.4.6  pytest==9.1.1  reportlab==5.1.0

PaddleOCR(
    text_detection_model_name="PP-OCRv5_mobile_det",
    text_recognition_model_name="korean_PP-OCRv5_mobile_rec",  # 반드시 함께 지정한다
    use_doc_orientation_classify=False, use_doc_unwarping=False, use_textline_orientation=False,
    text_det_limit_type="max", text_det_limit_side_len=1600,

```

   - 검출 모델 이름을 주면 `lang="korean"` 설정이 무시된다. 그래서 인식 모델 이름(`korean_PP-OCRv5_mobile_rec`)을 반드시 함께 지정한다. 지정하지 않으면 한국어가 아닌 기본 인식 모델로 읽는다.
   - 검출 크기 기본값은 팩스에서 정확도가 낮았다. 긴 변을 1600으로 맞추는 설정(`text_det_limit_type="max"`, `text_det_limit_side_len=1600`)이 나았다.

## 4. 폴더 구조

```
C:\nanum-mask\
├─ app\              프로그램 코드 (mask.py, extract.py, labels.py, rules.py, ner.py, review.py,
│                    review_server.py, learn.py, learnstate.py, fakeify.py, netguard.py, netguard.cjs)
├─ config\
│  ├─ labels.yaml    라벨 사전 (양식별로 추가)

│  ├─ review\        검수용 위치 목록(CSV)과 HTML — 원문 포함
│  ├─ learn\         검수 표시와 오답 기록 — 진짜 값 포함 (13절)
│  └─ work\          OCR 중간 결과
├─ models\           OCR·NER 모델 (설치 때 한 번 받음)

└─ tests\
   ├─ fake\  fake2\  가짜 공문과 정답표 (make_fake.py, make_fake2.py로 만든다)
   ├─ regress\base\  기존 시험 세트로 만든 회귀 기준 (13.4)

공문을 내려받는 방법(직원이 저장, 메일 자동 저장 등)은 이 프로그램 범위 밖이다. 어떤 방법이든 Claude가 원본 내용을 읽지 않은 채 `inbox\`에 파일을 저장해야 한다.

Claude Code가 원본 쪽 폴더를 읽지 못하게 `.claude\settings.json`에 아래 규칙을 넣는다(Windows 경로는 `/c/...` 형식으로 맞춘다). `secure\learn\`은 `secure\**` 규칙에 포함된다.

```json
{
  "permissions": {
    "deny": [
      "Read(//c/nanum-mask/inbox/**)",
      "Read(//c/nanum-mask/pending/**)",
      "Read(//c/nanum-mask/secure/**)",
      "Edit(//c/nanum-mask/secure/**)"
    ]
  }
}
```

이 규칙은 Bash·PowerShell 명령까지 완전히 막지는 못한다. 그래서 단체 서버의 `CLAUDE.md`에도 다음 문장을 추가한다.

```
- C:\nanum-mask\inbox, pending, secure 폴더의 파일 내용은 어떤 도구로도(Read, type, cat, Get-Content 포함) 열거나 출력하지 않는다.
- 공문 내용이 필요하면 C:\nanum-mask\masked\ 의 가린 사본만 읽는다.
- 정규식 수정안을 쓸 때는 C:\nanum-mask\learn\proposals\requests\ 의 가짜화한 요청만 읽는다.
```

## 5. 처리 단계

```
① inbox 감시 → ② 글자 읽기(OCR, 표 구조 유지) → ③ 라벨 칸 읽기 → 문서 명단 작성
   → ④ 가리기(문서 명단 전체 적용 + 규칙 + OCR 오독 규칙 + NER 보완 + 오답 노트 규칙 → 누출 재검사)
   → ⑤ 사람 검수(검수 화면에서 놓침·잘못 가림 표시) → ⑥ 가린 사본만 masked\ 로, 원본·대조표는 secure\ 에
   → ⑦ 오답 노트 반영(13절)
```

실행 명령은 다음과 같다.

| 명령 | 하는 일 |
|---|---|
| `python app\mask.py run` | inbox 전체를 처리한다 |
| `python app\mask.py review` | 검수 화면을 연다(`http://127.0.0.1:8765`) |
| `python app\mask.py approve <문서번호>` | 검수를 마친 사본을 `masked\`로 옮긴다 |
| `python app\learn.py ingest --out C:\nanum-mask` | 검수 표시를 오답 노트에 반영한다 |

Windows 작업 스케줄러로 10분마다 `run`을, 매일 저녁 `learn.py ingest`를 실행하는 설정은 직원이 원할 때 추가한다.

### ① 입력 받기

- 문서번호는 `YYYYMMDD-NNN` 형식으로 붙인다(예: `20261026-001`). 파일 이름에 고인 이름이 들어 있을 수 있으므로 **이후 모든 파일 이름은 문서번호만 쓴다.** 원래 파일 이름은 대조표에만 적는다.
- 원본은 처리 직후 `secure\originals\`로 옮긴다.

### ② 글자 읽기 — 표 구조를 지킨다

| 입력 | 방법 |
|---|---|
| HWP, HWPX, 글자가 든 PDF | `kordoc <파일> --silent --no-images -o secure\work\<문서번호>.md` — 표가 마크다운 표(병합 셀은 HTML table)로 나온다 |
| 스캔 PDF | `kordoc <파일> --ocr ...` |
| 팩스(TIFF·PNG·스캔 이미지) | 아래 팩스 절차 |

kordoc은 마크다운 특수 문자를 이스케이프하므로 `*`를 `\*`로 내보낸다. 7절 정규식은 이 표기를 받아야 한다.

팩스 절차:

1. 이미지를 8비트 회색조로 바꾼다. 이진화(흑백 두 값으로 바꾸기)와 잡음 제거는 하지 않는다. **맥 시험에서 회색조 변환 유무로 결과가 같았다.** 해가 없으므로 남겨 두지만 정확도가 오르기를 기대하지 않는다.
2. PaddleOCR(3절 설정)로 읽는다. 문서 방향 분류와 왜곡 보정 기능은 끈다.
3. 줄별 신뢰도의 평균이 기준값 미만이면 이미지를 180도 돌려 다시 읽고, 평균 신뢰도가 높은 쪽을 쓴다. 기준값은 처음에 0.8로 둔다.
   - 맥 시험에서 0.8 기준이면 팩스 8장 가운데 7장이 다시 읽기를 했다. 바로 놓인 장도 평균 신뢰도가 0.69~0.81이었기 때문이다. 다시 읽기는 결과를 해치지 않고 장당 시간만 늘린다. 뒤집어 넣은 2장은 모두 바르게 판별했다.
   - 단체 PC에서 가짜 팩스와 견본 팩스로 바로 놓인 장의 평균 신뢰도를 잰 뒤, 그 최저값보다 조금 낮게 기준을 정한다. 정한 값은 `policy.yaml`의 `fax_rotate_below`에 적는다.
4. 표 구조는 **방법 A를 기본으로 쓴다.** 고른 방향의 회색조 이미지를 PDF로 감싸 `kordoc --ocr`로 읽는다.
   - 방법 B(PaddleOCR 글자 상자를 y좌표로 묶어 행을 만드는 방법)는 맥 시험에서 장당 2.5초 빨랐지만 표 칸이 섞여 13건(이름 8, 주민번호 2, 주소 2, 전화 1)을 더 놓쳤다. 방법 B는 비교용 옵션(`--fax-method B`)으로만 남긴다.
5. 맥 CPU에서 팩스는 장당 약 11초(첫 장은 모델 로드로 약 20초), 스캔 PDF는 약 3초가 걸렸다. 평균 신뢰도와 낮은 신뢰도 줄 수는 검수 목록에 표시한다.

이 단계의 결과는 "표 행·열을 유지한 마크다운 텍스트" 하나이다. 이후 단계는 모두 이 텍스트의 글자 위치(offset)를 기준으로 동작한다.

팩스는 OCR이 읽는 단계에서 값을 잃을 수 있다. 맥 시험에서 팩스 8장의 정답 표기 32건이 OCR 단계에서 사라지거나 두 글자 이상 틀어졌다. 이런 값은 가린 사본에 원래 값으로 남지 않지만 이름 표기도 남지 않으므로 놓침 검사로 확인할 수 없다. **팩스 검수는 원본 이미지와 나란히 놓고 한다.**

### ③ 라벨 칸 읽기 — 그 문서용 명단 만들기

1. 표의 각 칸 글자를 정규화한다(공백·콜론·가운뎃점 제거, 괄호 안 설명 분리). 예: `성 명 :` → `성명`.
2. 정규화한 글자가 라벨 사전(6절)의 키와 같으면 값을 찾는다.
   - 같은 행의 오른쪽 칸이 값이다.
   - 오른쪽 칸이 없고 라벨이 머리 행에 있으면 같은 열의 아래 칸들이 값이다(여러 사람이 행으로 나열된 표).
   - **값 칸의 글자가 라벨 사전에 있는 낱말이면 값으로 보지 않는다.** 머리 행에 `| 성명 | 생년월일 | 관계 |`처럼 라벨이 나란히 있으면 오른쪽 칸 규칙이 "생년월일"을 이름으로 잡기 때문이다.
3. 표 밖의 줄은 `성명 : 홍길동`, `연고자(장남) 김철수` 같은 "라벨 + 구분자 + 값" 형태를 찾는다.
4. 값에서 항목별로 추출한다.
   - 이름: 앞뒤의 `故`, `고`, `망`, `님`, `씨`와 괄호 설명(`(남, 75세)`)을 떼고 한글 2~5자(또는 한자) 덩어리를 이름으로 본다. `홍길동, 이영희`처럼 여러 명이면 쉼표·가운뎃점·`및`으로 나눈다. `미상`, `없음`, `무연고`, `해당없음`, `불명`은 이름이 아니다.
   - 주민번호·전화번호: 7절 정규식으로 값 안에서 찾는다.
   - 주소: 칸 값 전체를 주소로 본다.
5. 찾은 값을 **문서 명단**에 넣는다. 각 항목은 `{종류, 값, 역할(사망자·연고자·신고인·담당공무원), 출처: 라벨}`이다.

### ④ 가리기

순서는 다음과 같다. 각 단계는 원문 글자 위치에 "가릴 구간"을 추가만 하고, 실제 치환은 마지막에 한 번 한다.

1. **문서 명단을 문서 전체에 적용**(8절). 표 칸뿐 아니라 본문, 머리말, 꼬리말에 다시 나온 이름과 번호도 같은 표기로 가린다.
2. **규칙 적용**(7절). 라벨 없이 나온 주민번호, 전화번호(한글 숫자 포함), 주소를 찾는다. 스캔·팩스 문서에는 OCR 오독 규칙(7.5절)을 더한다.
3. **오답 노트 규칙 적용**(13절). 직원이 승인한 정규식(`learn\rules_extra.yaml`)을 적용한다. `add_to_list: true`인 규칙이 찾은 이름은 문서 명단에 넣는다.
4. **NER 보완**(9절). 라벨에 없던 이름을 찾는다. 새 이름이 나오면 문서 명단에 추가하고 1번을 다시 실행해 같은 이름의 다른 등장 위치도 가린다.
5. **구간 병합**. 겹치는 구간은 긴 쪽을 남긴다. 출처 우선순위는 라벨 명단 > 규칙 > NER이다.
6. **치환**(10절). 뒤쪽 구간부터 바꿔 위치가 밀리지 않게 한다.
7. **누출 재검사**. 가린 결과를 다시 훑어 (a) 문서 명단의 모든 값과 변형, (b) 주민번호·전화번호 정규식이 하나라도 남아 있으면 그 문서를 "실패"로 표시하고 `masked\`로 보내지 않는다.

## 6. 라벨 사전 (`config\labels.yaml`)

양식이 새로 확인될 때마다 `forms:` 아래에 추가한다. 공통 라벨은 모든 문서에 적용하고, 양식별 라벨은 `match_any`의 문구가 문서에 있을 때만 추가로 적용한다. 오답 노트가 자동으로 찾은 라벨은 이 파일이 아니라 `learn\learned.yaml`에 쌓이고, 실행할 때 합쳐서 쓴다(13절).

```yaml
version: 1

common:
  NAME:
    사망자:   [성명, 사망자, 사망자성명, 고인, 고인성명, 망인, 성명(사망자)]
    연고자:   [연고자, 연고자성명, 유족, 보호자, 상주, 가족, 친족]
    신고인:   [신고인, 신고인성명, 신청인, 의뢰인, 발견자]
    담당공무원: [담당자, 담당, 주무관, 기안자, 검토자, 협조자]   # policy.mask_officials 따름
  RRN:      [주민등록번호, 주민번호, 주민등록, 외국인등록번호]
  PHONE:    [연락처, 전화번호, 전화, 휴대전화, 휴대폰, 핸드폰, 연락처(연고자), HP, Tel, TEL, ☎]
  ADDR:     [주소, 주민등록상주소, 최종주소지, 주소지, 거주지, 실거주지, 등록기준지, 본적, 사망장소, 발견장소]
  ORG_PHONE: [대표전화, 기관전화, 팩스, 전송, FAX]                # policy.mask_org_contact 따름

forms:
  - id: 무연고사망자_처리협조_예시
    match_any: ["무연고 사망자", "무연고사망자", "공영장례"]
    extra:
      NAME:
        사망자: [사망자인적사항, 대상자, 대상자성명]

```

- 라벨 비교는 공백을 지운 뒤 한다. 따라서 `성 명`, `성  명`, `성명 :`은 모두 `성명`과 같다.
- 라벨 사전에 있는 낱말(공통·양식별·오답 노트에서 배운 라벨 모두)은 이름 값이나 NER 결과에서 뺀다(3절, 9절).

## 7. 정규식 규칙 (`app\rules.py`)

모든 정규식은 숫자 앞뒤에 다른 숫자가 붙어 있지 않을 것(`(?<!\d)`, `(?!\d)`)을 조건으로 한다. OCR이 하이픈을 `–`, `—`, `~`, `ㅡ`로 읽는 경우가 있으므로 구분자 집합을 `[-–—~ㅡ.]`로 둔다.

### 7.1 주민등록번호

kordoc은 `*`를 `\*`로 내보낸다. 그래서 가림 문자 자리에 `\\?\*` 형태를 허용한다(v1과 달라진 곳).

```python
SEP = r"\s*[-–—~ㅡ]?\s*"
YYMMDD = r"\d{2}(0[1-9]|1[0-2])(0[1-9]|[12]\d|3[01])"
STAR   = r"(?:\\?\*)"                      # * 또는 kordoc의 \*
MASKCH = rf"(?:\d|{STAR}|[xX●○#])"

RRN_FULL      = rf"(?<!\d){YYMMDD}{SEP}[1-8]\d{{6}}(?!\d)"              # 500101-1234567, 5001011234567
RRN_BACK_HID  = rf"(?<!\d){YYMMDD}{SEP}[1-8]{MASKCH}{{6}}(?![\d*])"     # 500101-1******, 500101-1\*\*\*\*\*\*
RRN_ALL_HID   = rf"(?<!\d){YYMMDD}\s*[-–—]\s*(?:{STAR}|[xX●]){{7}}"     # 500101-*******
RRN_FRONT_HID = rf"(?:{STAR}|[xX●]){{6}}\s*[-–—]\s*[1-8]\d{{6}}(?!\d)"  # ******-1234567
```

- 뒷자리 첫 숫자는 외국인등록번호(5~8)까지 받도록 `[1-8]`을 기본으로 둔다.
- 생년월일만 단독으로 나온 경우(예: `1950. 1. 1.`)는 4가지 항목에 들지 않으므로 가리지 않는다. 단체가 원하면 `policy.mask_birthdate`로 켠다.
- 걸리면 안 되는 예: 문서번호 `복지정책과-12345`, 날짜 `2026-10-26`, 사업자등록번호 `123-45-67890`, 금액 `1,234,567원`.

### 7.2 전화번호

```python
D = r"[\d*xX]"     # 일부를 별표로 가린 번호도 잡는다
S = r"\s*[-.)\s]?\s*"

MOBILE   = rf"(?<!\d)01[016789]{S}{D}{{3,4}}{S}{D}{{4}}(?!\d)"                     # 010-1234-5678, 010 1234 5678, 010-****-5678
LANDLINE = rf"(?<!\d)\(?0(2|3[1-3]|4[1-4]|5[1-5]|6[1-4])\)?\s*[-.)\s]\s*{D}{{3,4}}\s*[-.\s]\s*{D}{{4}}(?!\d)"  # 02-123-4567, (031)123-4567
VOIP     = rf"(?<!\d)0(70|50\d){S}{D}{{3,4}}{S}{D}{{4}}(?!\d)"                     # 070, 0504 안심번호
INTL     = rf"\+82\s*[-]?\s*\(?0?(1[016789]|2|[3-6]\d)\)?{S}\d{{3,4}}{S}\d{{4}}(?!\d)"
REP      = rf"(?<!\d)1(5|6|8)\d{{2}}\s*[-.]\s*\d{{4}}(?!\d)"                        # 1588-0000 대표번호 → ORG_PHONE
```

- 일반전화는 구분자가 있어야 잡는다. 구분자 없는 9~10자리 숫자는 다른 번호일 가능성이 높기 때문이다. 라벨 칸 값 안에서는 구분자가 없어도 잡는다.
- 대표번호(`REP`)와 공문 머리·꼬리의 "전화·전송(팩스)" 번호는 `ORG_PHONE`으로 분류하고 `policy.mask_org_contact`에 따라 가린다.
- `LANDLINE`은 v1 그대로 쓴다. 맥 시험 중간에 "LANDLINE이 번호를 놓친다"고 적었으나, 원인은 견본 HWPX를 만들 때 "1."이 "가."로 바뀐 견본 생성 오류였다. 그 판단은 철회한다.

### 7.3 한글 숫자로 적은 전화번호

전사 메모나 OCR 결과에 `공일공 일이삼사 오육칠팔`처럼 적힌 번호를 잡는다.

1. 숫자 대응표: `공·영·빵→0, 일→1, 이→2, 삼→3, 사→4, 오→5, 육·륙→6, 칠→7, 팔→8, 구→9`. 오답 노트가 배운 오독 글자(예: `철→7`)는 `learn\learned.yaml`의 `ocr_confusions`에서 읽어 이 표에 더한다.
2. 이 글자와 아라비아 숫자, 공백, `-`, `.`만으로 이어진 구간을 찾는다.
3. **구간 안의 한글 숫자가 3글자 이상일 때만** 다음 단계로 간다. 이 조건이 없으면 `2026.10.18.오 2시`의 "오"를 숫자로 보아 날짜를 전화번호로 잡는다(v1과 달라진 곳).
4. 구간을 숫자로 바꿨을 때 9~11자리이고 `0`으로 시작하면 7.2 전화번호 정규식(구분자 조건 없이)을 바꾼 문자열에 적용한다. 일치하면 원래 구간 전체를 `[전화번호]`로 가린다.
5. `이`, `오`, `사`처럼 흔한 글자 때문에 생기는 오탐을 막기 위해 숫자 글자가 9개 이상 이어져야 하고 `공`·`영`·`0`으로 시작해야 한다는 조건을 둔다.
6. 섞인 표기(`010-일이삼사-5678`)도 같은 방법으로 잡힌다.

### 7.4 주소

```python
SIDO = (r"(서울특별시|서울시|서울|부산광역시|부산시|부산|대구광역시|대구|인천광역시|인천|"
        r"광주광역시|광주|대전광역시|대전|울산광역시|울산|세종특별자치시|세종시|세종|"
        r"경기도|경기|강원특별자치도|강원도|강원|충청북도|충북|충청남도|충남|"
        r"전북특별자치도|전라북도|전북|전라남도|전남|경상북도|경북|경상남도|경남|"
        r"제주특별자치도|제주도|제주)")
SIGUNGU = r"([가-힣]{1,5}(시|군|구)\s*){1,2}"
EMD     = r"([가-힣0-9]{1,8}(읍|면)\s*)?"
ROAD    = r"[가-힣0-9·]{1,15}(로|길)(\s*\d{1,4}번?(길|가길))?\s*\d{1,5}(-\d{1,5})?"
JIBUN   = r"[가-힣0-9·]{1,10}(동|가|리)\s*(산\s*)?\d{1,5}(-\d{1,5})?(번지)?"
DETAIL  = r"(\s*,?\s*(\d{1,4}\s*동)?\s*(\d{1,5}\s*호|\d{1,3}\s*층)?(\s*\([^)\n]{1,30}\))?)?"

ADDR_FULL  = SIDO + r"\s*" + SIGUNGU + EMD + "(" + ROAD + "|" + JIBUN + ")" + DETAIL
ADDR_NOSIDO= SIGUNGU + EMD + "(" + ROAD + "|" + JIBUN + ")" + DETAIL
```

- `ADDR_FULL`은 문서 어디서나 적용한다. 시·도부터 상세주소(동·호·층·괄호 건물명)까지 한 덩어리로 `[주소]`로 바꾼다.
- 시·도가 빠진 `ADDR_NOSIDO`는 다음 경우에만 적용한다.
  - 라벨 칸 값 안이다.
  - 앞 15글자 안에 `주소`, `거주`, `주거지`, `사망장소`, `소재` 같은 단어가 있다.
  - **주소 바로 뒤에 거처를 뜻하는 낱말(`고시원`, `반지하`, `쪽방`, `여관`, `원룸` 등)이 온다(v1과 달라진 곳).** 맥 시험에서 본문의 "가상시 샘플동 123-4번지 반지하 방에서", "가나구 별빛로 7 고시원에서"를 v1 규칙이 놓쳤다.
- 공문을 보낸 기관의 주소(머리·꼬리의 `우 00000 ... 기관명`)는 `ORG_ADDR`로 분류하고 `policy.mask_org_contact`를 따른다.
- 시·군·구까지만 남기고 나머지를 가리는 방식은 이번 범위에 넣지 않는다.

### 7.5 스캔·팩스용 OCR 오독 규칙 (새 절)

스캔 PDF와 팩스는 OCR이 글자를 틀리게 읽는다. 아래 규칙은 **스캔·팩스 문서에만** 켠다. 텍스트 PDF·HWP에 켜면 날짜·문서번호를 잘못 잡을 위험만 늘어난다. 맥 시험에서 이 규칙으로 스캔 놓침이 4건에서 0건, 팩스 놓침이 14건에서 0건이 되었다. 모든 규칙은 날짜·사업자번호·문서번호가 걸리지 않는지 단위 시험으로 확인한다(맥 시험 66건 통과).

| 규칙 | 실제로 본 오독(가짜 값) | 잡는 방법 |
|---|---|---|
| 별표 일부 누락 | `450315-2****` | YYMMDD-[1-8] 뒤에 별표가 2~6개만 있어도 주민번호로 본다 |
| 별표 전체 누락 | `4803021` | 앞뒤에 숫자가 없는 YYMMDD+[1-8](7자리)을 주민번호로 본다 |
| ☎를 숫자 8로 읽음 | `8032-7654321`, `802-2100-3456` | 8 바로 뒤에 지역번호·휴대전화 번호가 오는 형태를 잡는다 |
| 한글 숫자 오독 | `공일공 일이삼사 오육철필`, `공일금 오오오오 공일공일` | `공일`·`영일`·`공이`로 시작하고 숫자 글자 비율이 0.7 이상이면 전화번호로 본다 |
| 번호 잔해 | `8053-200-111`, `010-01이4455`, `82107788` | 0·80·82로 시작하고 아라비아 숫자 7개 이상, 한글 숫자 2개 이하인 덩어리를 전화번호로 본다 |
| 주소 라벨 깨짐 | `가온구은하로33`(라벨 "주소"가 "주"로 깨짐) | 문맥 없이도 시군구·도로명·번호가 붙어 이어지는 형태를 잡는다 |
| 시·도·시군구 표기 깨짐 | `서율특별시`, `가상서 생플동 123-4` | 깨진 시·도 표기 목록과 "○○동 숫자-숫자" 지번 형태를 잡는다 |
| 줄 머리 번호가 이름에 붙음 | `2오말순 님은` | NER에 넘기기 전에 줄 머리 번호("2.", "2")를 공백으로 바꾼다. 글자 위치는 바꾸지 않는다 |

- 새로운 오독이 검수에서 나오면 오답 노트(13절)가 처리한다. 오독 글자 하나(예: `철`을 `7`로 읽음)는 자동으로 대응표에 들어가고, 새로운 모양은 가짜화한 수정 요청이 되어 직원 승인을 거쳐 규칙이 된다.

## 8. 문서 명단을 문서 전체에 적용하는 방식 (`app\labels.py`)

명단의 이름 하나(예: 홍길동)로부터 아래 변형을 만들어 문서 전체를 찾는다.

| 변형 | 예 | 처리 |
|---|---|---|
| 그대로 | 홍길동, 홍길동의, 홍길동님 | 자동으로 가린다 |
| 글자 사이 공백 | 홍 길 동, 홍 길동 | 자동으로 가린다 (`홍\s*길\s*동`) |
| 앞에 붙는 말 | 故홍길동, 고 홍길동, 망 홍길동 | 앞말은 남기고 이름만 가린다 |
| 성을 뺀 이름 + 호칭 | 길동 씨, 길동님, 길동이가 | 자동으로 가리고 "검수 필요"로 표시한다 |
| 성 + 호칭 | 홍 씨, 홍씨 | 자동으로 가리고 "검수 필요"로 표시한다 |
| OCR 한 글자 오류 | 홍길둥 (3글자 이상 이름에서 한 글자만 다름) | 자동으로 가리고 "검수 필요"로 표시한다 |
| 한자 | 洪吉童 (라벨 값이 한자일 때) | 자동으로 가린다 |

- 두 글자 성(남궁, 선우, 제갈, 황보, 독고, 사공, 서문)을 먼저 확인한 뒤 성과 이름을 나눈다.
- 경계 조건: 이름 앞 글자가 한글이면 앞말(`고`, `망`, `故`)일 때만 인정한다. 이름 뒤에는 조사(`은·는·이·가·을·를·의·에게·께서·와·과`)와 호칭(`님·씨·군·양`)이 붙어도 인정한다. 그 밖에 한글이 이어지면 다른 단어의 일부로 보고 가리지 않는다.
- 성을 뺀 이름(`길동`)은 뒤에 호칭이나 조사가 붙은 경우에만 찾는다. 단독 두 글자는 일반 낱말과 겹칠 수 있기 때문이다.
- 주민번호와 전화번호도 명단 값의 숫자만 남긴 형태(`5001011234567`, `01012345678`)와 공백·하이픈 변형을 모두 찾는다.
- 같은 값은 문서 안에서 언제나 같은 표기로 바꾼다. 홍길동은 몇 번 나와도 `[이름1]`이다.
- **이름 필터(v1과 달라진 곳)**. 명단에 넣기 전에 아래 낱말을 이름에서 뺀다.
  - 지명: 시·군·구·동·읍·면으로 끝나는 낱말과 그 앞부분(예: `가온`, `나래구`, `은하동`). 문서의 주소 값에 나온 지명 낱말도 뺀다.
  - 라벨 낱말: 라벨 사전에 있는 낱말(예: `기안자`).
  - "지명+장": `나래구청장`, `가온군수`처럼 지명 뒤에 직함이 붙은 낱말. 이 필터가 없으면 `나래구`를 이름으로 가리면서 금지값 `구청`까지 가린다.
  - 오답 노트의 예외 낱말(`learn\learned.yaml`의 `exceptions`).

## 9. NER 보완 (`app\ner.py`) — 필수

- **NER은 끄면 안 된다.** 맥 시험에서 NER을 끄면 팩스 21건, 스캔 10건, 텍스트 4건을 놓쳤고, 놓친 것이 모두 이름이었다. NER에 드는 CPU는 장당 약 0.05초(첫 장 약 1.4초)이다.
- 모델은 `atonlee/koelectra-ko-pii-ner`(라이선스 apache-2.0)를 쓴다. 이 모델은 사람 이름을 **`NAME` 태그**로 낸다(v1이 가정한 `PS`가 아니다). 주소는 `ADDR` 태그로 낸다. 다른 모델로 바꾸면 모델 카드에서 라이선스와 태그 체계를 확인하고 직원에게 알린다.
- 모델은 설치할 때 `C:\nanum-mask\models\ner\koelectra-ko-pii-ner\`에 한 번만 받고(약 55MB), 실행 때는 `local_files_only=True`로 읽는다.
- 입력은 ② 단계 텍스트 원문이다(PC 메모리 안에서만 처리한다). 줄 머리 번호는 공백으로 바꿔 넣는다(7.5절). 512토큰을 넘으면 줄 단위로 나눠 넣는다.
- `NAME`으로 나온 구간 가운데 한글 2~4자이고 이미 가린 구간과 겹치지 않는 것만 쓴다. 점수 0.6 이상은 자동으로 가리고 모두 "검수 필요(NER)"로 표시한다. 0.6 미만은 가리지 않고 검수 목록에만 "후보"로 올린다.
- 8절의 이름 필터(지명, 라벨 낱말, "지명+장", 예외 낱말)를 NER 결과에도 똑같이 적용한다.
- 오탐 방지 목록(`config\ner_stopwords.txt`)에 `담당`, `주무관`, `장례`, `유족`, `연고자`, `공영장례` 같은 낱말을 넣는다. 검수에서 나온 오탐은 오답 노트가 `learned.yaml`의 예외 목록에 쌓는다(13절).
- 담당 공무원 이름으로 판단되는 경우(앞뒤에 `주무관`, `팀장`, `과장`, `담당`)는 역할을 `담당공무원`으로 두고 `policy.mask_officials`를 따른다.
- NER로 찾은 새 이름은 문서 명단에 넣고 8절을 다시 적용한다.
- 맥 시험의 최종판에서 팩스는 이름이 아닌 낱말 18건을 더 가렸다(OCR이 틀리게 읽은 "배우자", "추부관" 등). 더 가린 것은 덜 가린 것보다 안전하다. 검수 화면에서 "잘못 가림"으로 표시하면 오답 노트가 예외 낱말로 배운다.

## 10. 치환 표기와 가린 사본 형식

- 이름: 문서 안에서 처음 등장 순서대로 `[이름1]`, `[이름2]` … 단, 사망자 칸에서 나온 이름을 `[이름1]`로 먼저 배정한다.
- 주민등록번호: `[주민번호]`, 전화번호: `[전화번호]`, 주소: `[주소]`. 같은 문서에서 서로 다른 번호를 구분해야 하면 `policy.number_all: true`로 `[전화번호1]`, `[전화번호2]`처럼 번호를 붙인다(기본값 false).
- 기관 연락처를 가리는 경우: `[기관전화]`, `[기관주소]`. 담당 공무원 이름은 `[이름n]`으로 가리고 역할만 따로 적는다.
- 가린 사본은 `masked\<문서번호>.md`로 저장한다. 표 구조는 그대로 두고, 맨 위에 값이 없는 정보만 담은 머리말을 붙인다.

```markdown
---
doc_id: 20261026-001
masked: true
source_type: pdf-text      # pdf-text | pdf-ocr | hwp | hwpx | fax
roles: {이름1: 사망자, 이름2: 연고자, 이름3: 담당공무원}
review: approved           # approved | pending | failed
ocr_mean_confidence: null
---

| 구분 | 내용 |
|---|---|
| 성명 | [이름1] |
| 주민등록번호 | [주민번호] |
| 주소 | [주소] |
| 연고자 | [이름2] (장남) |
| 연락처 | [전화번호] |

[이름1] 님의 장례와 관련하여 연고자 [이름2] 씨에게 연락하였으나 …
```

## 11. 대조표 — 별도 로컬 파일로만

- `secure\maps\<문서번호>.map.json`에 문서별로 저장한다.

```json
{
  "doc_id": "20261026-001",
  "original_filename": "(원래 파일 이름)",
  "created": "2026-10-26T15:30:00+09:00",
  "map": {"[이름1]": "홍길동", "[이름2]": "김철수", "[주민번호]": ["500101-1234567"], "[전화번호]": ["010-1234-5678"]}
}
```

- 대조표는 `masked\`, 구글 드라이브, NAS, 슬랙, 메일 어디에도 복사하지 않는다. Claude Code도 읽지 않는다.
- 가린 사본을 원래 값으로 되돌리는 기능(`python app\mask.py unmask <문서번호>`)은 직원이 직접 실행하는 용도로만 만들고, 결과를 `secure\` 안에만 쓴다.
- Windows BitLocker나 폴더 암호화(EFS)로 `secure\`를 보호할 것을 직원에게 권한다. 보관 기간이 정해지면 기간이 지난 대조표와 원본을 지울 대상 목록을 만들어 직원에게 보여 주고, 삭제는 직원이 승인한 뒤에 한다.

## 12. 검수 화면 (`app\review_server.py`, `app\review.py`)

- 직원은 `python app\mask.py review`를 실행하고 PC 안의 브라우저로 `http://127.0.0.1:8765`를 연다. 첫 화면에 검수 대기 문서 목록이 나온다.
- 문서 화면은 원문 텍스트를 보여 주고, 가린 구간을 종류별 색 배경으로 표시한다. 직원은 두 가지 표시만 남긴다.
  - **놓침**: 가려야 했는데 남은 글자를 마우스로 끌어 선택하고 `이름`·`주민번호`·`전화`·`주소` 버튼 가운데 하나를 누른다.
  - **잘못 가림**: 가리지 말아야 할 곳의 색 배경을 클릭한다.
  - 표시 목록을 확인하고 `저장`을 누른다. 표시는 `secure\learn\marks\<문서번호>.json`에 저장된다.
- 이 방식을 고른 이유는 다음과 같다.
  - 직원이 CSV·JSON 파일을 직접 고치지 않아도 된다. 글자 선택과 버튼 하나로 끝난다.
  - 글자 위치(offset)는 프로그램이 적는다. 직원이 위치나 원문을 손으로 옮겨 적다가 틀릴 일이 없다.
  - 브라우저만 있으면 되고 따로 설치할 프로그램이 없다. 서버는 파이썬 표준 라이브러리로 만든다.
- 보안 조건은 다음과 같다.
  - `127.0.0.1`에만 연다. 요청의 Host 헤더가 `127.0.0.1:포트`나 `localhost:포트`가 아니면 거부한다.
  - 저장·승인 요청(POST)은 실행할 때마다 새로 만드는 토큰(`X-Token` 헤더)이 맞아야 처리한다.
  - 외부 글꼴·스크립트를 불러오지 않는다. 응답에 `Content-Security-Policy: default-src 'self'` 계열 헤더를 붙인다.
  - 화면 출력과 로그에 값을 쓰지 않는다.
- `secure\review\<문서번호>.review.csv`(위치 목록)와 `.review.html`(정적 비교 화면)은 v1처럼 만들어 둔다. 검수 화면이 열리지 않을 때 대신 본다.
- 검수 방식은 `policy.review_mode`로 정한다. **첫 주는 `all`(모든 문서를 사람이 확인)**로 둔다. 그 뒤 `flagged`(검수 필요 표시가 있거나 OCR 신뢰도가 낮은 문서만 확인)로 바꿀지는 단체가 정한다.
- 표시를 저장한 뒤 `approve`로 그 문서를 승인하기 전에, 놓침 표시가 있는 문서는 오답 노트 반영(`learn.py ingest`) 뒤 `run`을 다시 실행해 다시 가린 사본으로 승인한다. 반영된 낱말·규칙으로 고쳐지지 않은 놓침은 직원이 decision 파일(v1 방식)이나 수기로 가린 뒤 승인한다.

## 13. 오답 노트 (새 절)

검수에서 나온 놓침과 잘못 가림을 모아 다음 문서부터 같은 실수를 하지 않게 한다. 낱말 목록을 고치는 일은 사람 승인 없이 자동으로 하고, 정규식을 고치는 일은 가짜화한 사례만 보고 Claude Code가 수정안을 쓴 뒤 직원이 승인한다. 어느 쪽이든 회귀 시험을 통과해야 적용한다.

### 13.1 순환

```
검수 화면 표시 ─▶ learn.py ingest ─┬─▶ 낱말 후보(라벨·예외·오독 글자) ─▶ 회귀 시험 ─┬─ 통과 ─▶ learned.yaml (자동 반영)
 (놓침·잘못 가림)                  │                                               └─ 실패 ─▶ held.jsonl (보류)
                                   ├─▶ 남은 놓침 ─▶ 가짜화 ─▶ 수정 요청 ─▶ Claude Code 수정안 ─▶ check(회귀 시험)
                                   │                                         ─▶ 검수 화면에서 직원 승인 ─▶ rules_extra.yaml
                                   └─▶ 모든 표시 ─▶ 가짜화 ─▶ 회귀 사례(regress\cases) ─▶ 다음 회귀 시험에 포함
주마다 learn.py report ─▶ learn\reports\주간보고-날짜.md (발송하지 않음)
```

### 13.2 파일

| 위치 | 내용 | 진짜 값 |
|---|---|---|
| `secure\learn\marks\<문서번호>.json` | 검수 화면에서 남긴 표시 `{type: miss/over, kind, start, end, text}` | 있음 |
| `secure\learn\notebook.jsonl` | 반영한 표시의 기록 | 있음 |
| `secure\learn\ingested.json` | 이미 반영한 표시 파일의 지문(같은 표시를 두 번 반영하지 않는다) | 없음 |
| `secure\learn\pending_words.json` | 이름처럼 보여 직원 판단을 기다리는 낱말 | 있음 |
| `learn\learned.yaml` | 자동 반영한 낱말: `labels`(역할별 라벨), `exceptions`(이름 아님), `ocr_confusions`(오독 글자→숫자) | 없음 |
| `learn\rules_extra.yaml` | 직원이 승인한 정규식 | 없음 |
| `learn\held.jsonl` | 회귀 시험에 걸려 보류한 후보와 이유 | 없음 |
| `learn\proposals\requests\q-*.json` | 가짜화한 수정 요청 | 없음 |
| `learn\proposals\drafts\d-*.yaml` | Claude Code가 쓴 수정안 | 없음 |
| `learn\proposals\status.json` | 수정안의 검사·승인 상태 | 없음 |
| `learn\regress\cases\c-*.json` | 가짜화한 지난 오답(회귀 세트) | 없음 |
| `learn\history.jsonl` | 사건 기록(반영·보류·검사·승인) | 없음 |
| `learn\reports\` | 주간 보고 | 없음 |

`learned.yaml`과 `rules_extra.yaml`은 사람이 읽을 수 있는 YAML이다. 잘못 들어간 항목은 직원이 직접 지울 수 있다(지운 뒤 `learn.py status`로 확인한다).

### 13.3 자동 반영 범위 — 낱말 목록까지만

| 표시 | 프로그램 판단 | 반영 |
|---|---|---|
| 잘못 가림 | 가린 낱말이 표 칸 전체이거나 콜론 앞 낱말이다(예: 표 칸 `변사자`) | 라벨 목록에 추가한다. 역할은 낱말에서 추정한다(`변사`→사망자, `보호`→연고자, 판단이 안 되면 연고자) |
| 잘못 가림 | 이름처럼 보이지 않는 낱말이다(예: `가람수산`, `수신`) | 예외 목록에 추가한다 |
| 잘못 가림 | 이름처럼 보이는 낱말이다(성씨 글자로 시작하는 2~3음절, 두 글자 성씨로 시작하는 4음절) | 자동 반영하지 않는다. 검수 화면의 "승인 대기 낱말"에 올려 직원이 "이름 아님"을 누를 때만 예외 목록에 넣는다 |
| 놓침(주민번호·전화) | 숫자 자리에 숫자가 아닌 글자가 있다(예: `철`, `실`, `말`) | 그 글자를 오독 글자 대응표에 추가한다(앞뒤 자리 모양으로 숫자를 추정한다) |
| 놓침 | 값 앞의 칸이나 콜론 앞 낱말이 라벨 사전에 없다(예: OCR이 깨뜨린 `입원전추소`) | 그 낱말을 해당 종류의 라벨로 추가한다 |
| 놓침 | 위 방법으로 고쳐지지 않는다 | 가짜화한 수정 요청을 만든다(13.6) |

- 자동 반영은 목록에 낱말을 추가하는 일까지만 한다. 정규식, 코드, 정책은 자동으로 바꾸지 않는다.
- 후보를 한꺼번에 회귀 시험에 넣고, 실패하면 하나씩 다시 넣어 통과한 것만 반영한다.

### 13.4 회귀 시험

후보를 반영하기 전과 반영한 뒤를 비교한다. **하나라도 나빠지면 반영하지 않고 `held.jsonl`에 보류한다.**

1. 기존 시험 세트(`tests\regress\base\`): 가짜 공문 26건의 OCR 결과 텍스트와 정답표이다. OCR을 다시 돌리지 않고 처리 단계만 다시 돌려 문서별 놓침과 금지값 가림을 센다(26건에 맥에서 약 4초).
2. 지난 오답 회귀 사례(`learn\regress\cases\`): 가짜화한 지난 오답마다 "가려야 할 글자(must_mask)"와 "가리면 안 되는 글자(must_not)"를 확인한다.
3. 규칙 단위 시험(`pytest tests\test_rules.py`).

- 기준 세트는 설치 직후 한 번 만든다: `python app\learn.py init-base --from tests\out\<첫 시험 실행> --fake tests\fake`. 이미 있으면 덮어쓰지 않는다.
- 비교는 문서·사례별로 한다. 합계가 같아도 한 문서에서 놓침이 늘면 거부한다.

### 13.5 가짜화 규칙 (`app\fakeify.py`)

진짜 값이 들어간 오답을 Claude Code와 회귀 세트에 넘기기 전에, 글자 모양은 남기고 값만 바꾼다.

- 글자 수와 위치를 그대로 둔다(한 글자를 한 글자로 바꾼다). 그래서 표 구조, 구분자, 라벨 낱말, 오답의 위치가 남는다.
- 남기는 것: 구분자(공백, `-`, `*`, 괄호 등), 라벨 낱말(배운 라벨 포함), 시·도 이름, 주소 접미사(시·군·구·동·로·길, `-ro`·`-gil`), 전화 앞자리(010, 02 등), 글자 모양(숫자 / 한글 숫자 / 오독 글자 / 라틴 글자 / 한자), HTML 태그.
- 바꾸는 것:
  - 이름 음절(성씨는 다른 성씨로), 라틴 글자(대소문자 유지), 한자
  - 숫자(자리마다 다른 숫자로), 한글 숫자(다른 숫자의 한글 숫자로), 오독 글자(새 숫자에 맞춘 비슷한 오독 글자로)
  - 주소의 지명 음절. 같은 지명이 기관 이름(`가온군수`, `가온대학교병원`)이나 다른 줄에 다시 나와도 함께 바꾼다.
  - 문서 명단의 이름이 오답 창 밖의 다른 줄에 다시 나와도 함께 바꾼다.
  - 4자리 이상 이어진 숫자 묶음(사업자번호 등)은 구분자를 사이에 둔 부분까지 통째로 바꾼다.
- **원래 값이 남았는지 검사한다.** 검사 항목은 다음과 같다.
  - 바꿔야 할 위치마다 글자가 실제로 바뀌었는가
  - 원래 값 전체가 결과 어디에도 없는가
  - 원래 번호의 숫자 4자리가 연속으로 결과에 나오지 않는가(구분자는 건너뛰고 비교한다)
  - 주소의 지명 핵심어, 라틴 낱말, 이름 음절 묶음이 남지 않았는가
  - 검사에 실패하면 다른 씨앗값으로 다시 만든다. 29번까지 실패하면 그 사례와 요청을 만들지 않고 실패 건수만 기록한다. 검사 메시지에는 진짜 값을 넣지 않는다.
- 독립 검사(`tests\check_fake_leak.py`): 정답표에 적힌 가짜 공문의 모든 값을 기준으로 `learn\` 폴더 전체를 다시 훑는다. 가짜 세트로 시험할 때 실행한다.

### 13.6 수정 요청과 수정안

- 수정 요청(`learn\proposals\requests\q-*.json`)에는 다음이 들어간다. 모두 가짜화한 값이다.
  - `window`: 놓친 자리 앞뒤 2줄(최대 300자)
  - `target`: 창 안에서 놓친 글자의 위치
  - `kind`: 이름·주민번호·전화·주소
  - `masked_in_window`: 창 안에서 이미 가린 구간
  - `reproduced`: 가짜화한 창을 지금 규칙으로 다시 돌렸을 때도 놓치는지(false면 가짜화한 값으로는 재현되지 않는다는 뜻이다)
  - `shape`: 글자 모양 요약(숫자·한글·라틴 개수 등)
- Claude Code는 요청만 읽고 수정안(`learn\proposals\drafts\d-<이름>.yaml`)을 쓴다. 형식은 다음과 같다.

```yaml
kind: NAME                 # NAME / RRN / PHONE / ADDR
pattern: '(?:성명|이름)\s*\(\s*영문\s*\)\s*\|?\s*[:：]?[ \t]*(?P<n>[A-Z][A-Za-z\-]*(?:[ \t]+[A-Z][A-Za-z\-]*){0,4})'
scope: all                 # all: 모든 문서 / ocr: 스캔·팩스만
add_to_list: true          # 찾은 이름을 문서 명단에 넣어 다른 등장도 가린다
note: 성명(영문) 칸 뒤의 로마자 이름 1~5단어를 가린다
tests:
  hit:  ['| 성명(영문) | NGUYEN VAN AN |']
  miss: ['| 성명 | 홍길동 |', '| 성명(영문) | |']
request_ids: [q-xxxxxxxx]
```

  - 이름 그룹 `n`이 있으면 그 부분만 가린다.
  - 수정안은 낱말 목록으로 고칠 수 없는 모양에만 쓴다. 특정 이름이나 번호를 정규식에 넣지 않는다.
- `python app\learn.py check <수정안>`이 다음을 확인한다: 정규식 오류 없음, `hit` 예문에 모두 맞음, `miss` 예문에 하나도 맞지 않음, 연결한 요청의 놓친 자리를 덮음, 13.4 회귀 시험 통과.
- **직원 승인은 검수 화면의 "수정안" 탭에서 `승인` 버튼 하나로 한다.** 화면에는 수정안의 설명(note), 검사 결과, 고치는 요청 수가 나온다. 검사를 통과하지 못한 수정안은 승인 버튼을 눌러도 적용되지 않는다. 승인하면 `rules_extra.yaml`에 승인 시각과 승인자가 함께 기록된다. 명령으로는 `python app\learn.py approve <수정안> --who 이름`이다.
- 학습 상태가 바뀐 뒤에 승인하면 검사를 다시 돌린 뒤 적용한다.

### 13.7 주간 보고

`python app\learn.py report --days 7`이 `learn\reports\주간보고-YYYY-MM-DD.md`를 만든다. 발송하지 않는다. 진짜 값은 넣지 않는다.

- 놓침·잘못 가림 표시 건수(종류별)
- 자동 반영한 낱말(라벨·예외·오독 글자). 이 낱말들은 이름이 아닌 것으로 판정된 낱말이므로 보고에 적는다.
- 보류한 후보와 이유
- 승인 대기 수정안과 그 검사 결과
- 승인 대기 낱말 수(낱말 자체는 적지 않는다)

### 13.9 맥 학습 실험 결과

가짜 공문 12건(N01~N12)을 절반으로 나눠 시험했다. 학습 절반(L: N01, N02, N04, N05, N06)의 검수 표시를 흉내 내 `learn.py ingest`로 반영하고, Claude Code 에이전트가 가짜화한 수정 요청만 읽고 수정안 6개를 썼다. 6개 모두 검사를 통과해 시험 목적으로 승인했다. 그 뒤 나머지 절반(H: N03, N07~N12)과 기존 26건으로 채점했다. 채점은 같은 OCR 결과를 학습 전 상태와 학습 후 상태로 다시 처리해 비교했다(엄격 채점).

| 대상 | 놓침(처음 → 학습 후) | 금지값 가림(처음 → 학습 후) |
|---|---|---|
| L 절반 5건(학습에 쓴 문서) | 8 → 0 | 1 → 0 |
| **H 절반 7건(학습에 쓰지 않은 문서)** | **9 → 7** | 1 → 1 |
| 기존 26건 | 4 → 2 | 0 → 0 |

자동 반영한 낱말은 라벨 3개(`변사자`, `방인`, OCR이 깨뜨린 `입원전추소`), 예외 2개(`가람수산`, `수신`), 오독 글자 3개(`철`, `실`, `말`)이다. 승인한 수정안 6개는 다음과 같다.

| 수정안 | 고치는 모양 | 범위 |
|---|---|---|
| `d-kin-name-ssi` | 가족 관계어(아들·딸·형 등) 뒤 2~4글자 + 씨/님 | 모든 문서. 기존 26건의 엄격 채점 놓침 4건 중 2건도 고쳤다 |
| `d-hanja-paren-name` | 괄호 안 한자 이름 + 씨/님 | 모든 문서 |
| `d-eng-name-field` | `성명(영문)` 칸 뒤 로마자 이름 | 모든 문서 |
| `d-roman-road-addr` | 쉼표 뒤 `-ro`·`-gil`·`-daero`로 쓴 로마자 도로명 | 모든 문서 |
| `d-socialworker-name-phone` | 사회복지사(오탈자 포함) 뒤 이름 + 전화번호 | 스캔·팩스 |
| `d-numbered-death-name` | 번호 항목 첫머리 이름 + 날짜 + 사망 낱말 | 스캔·팩스. 범위가 매우 좁다 |

일반화되지 않은 사례(학습에 쓰지 않은 문서에서 남은 놓침 7건과 금지값 가림 1건):

- N10(외국인 사망자): 4 → 2. 영문 이름과 영문 주소는 고쳐졌다. 한글로 음역한 6음절 이름(띄어 쓴 형태와 붙여 쓴 형태 2건)은 남았다. 다른 회사 이름(봉제 업체)을 가린 1건도 남았다. 예외 목록은 배운 낱말 하나만 고치므로 다른 회사 이름에는 적용되지 않는다.
- N11(텍스트, `O`·`l` 오독과 띄어 쓴 번호): 3 → 3. 학습 절반에 같은 유형의 오답이 없었다.
- N12(팩스, 요양원 새 양식): 2 → 2. 입소자 칸의 이름과 주소가 남았다. 학습 절반에 없던 양식이다.

정리하면, 오답 노트는 이미 본 모양을 확실히 고치고 기존 문서를 나빠지게 하지 않는다. 처음 보는 양식과 처음 보는 오독은 고치지 못하므로 검수 화면에서 사람이 확인하는 단계는 계속 필요하다. 이 결과는 가짜 공문 12건으로 얻은 것이므로 단체 PC에서 실제 공문으로 다시 확인한다.

가짜화 검사: 가짜화 단계의 자체 검사 실패는 0건이다. 독립 검사(`check_fake_leak.py`)로 학습 폴더의 파일 23개를 훑었을 때, 원래 문서의 값이 그 문서에서 나온 사례나 요청에 남은 경우("자기 문서")는 0건이다. 걸린 27건은 가상 지명 `가람`이 예외 낱말 `가람수산`과 같은 글자인 경우, 수정안 예문에 에이전트가 지어 쓴 숫자가 다른 문서의 숫자 4자리와 우연히 겹친 경우, 흔한 성씨 `NGUYEN`을 예문에 쓴 경우였다.

## 14. 단체가 정할 항목 (`config\policy.yaml`)

```yaml
mask_officials: true        # (b) 담당 공무원 이름을 가릴지. 정하기 전 기본값 true
mask_org_contact: true      # (b) 기관 대표전화·팩스·기관 주소를 가릴지. 정하기 전 기본값 true
keep_originals: true        # (c) 원본을 보관할지
retention_days: null        # (c) 원본·대조표 보관 기간(일). 정하기 전에는 지우지 않는다
review_mode: all            # 첫 주는 all, 이후 flagged 전환 여부는 단체가 정한다
mask_birthdate: false       # 생년월일 단독 표기를 가릴지
number_all: false           # 전화번호·주소에도 번호를 붙일지
fax_rotate_below: 0.8       # 팩스 평균 신뢰도가 이 값보다 낮으면 180도 돌려 다시 읽는다(5절, 단체 PC에서 다시 정함)
```

- (a) OCR이 표를 깨뜨리지 않아야 한다. 칸 이름과 값이 엇갈리면 이 방식이 무너진다. PDF·HWP 공문은 kordoc이 표를 보존하고, 팩스는 견본으로 시험해 봐야 한다. 이것은 결정 사항이 아니라 시험으로 확인할 조건이다.
- (b) 담당 공무원 이름과 기관 대표 전화번호까지 가릴지 단체가 기준을 정한다.
- (c) 원본 보관 여부와 기간은 단체가 정한다. 검수 표시(`secure\learn\`)도 같은 기간을 따른다.

## 15. 가짜 데이터로 시험하는 절차

실제 공문은 쓰지 않는다. 아래 순서로 시험하고 결과를 직원에게 보고한다.

1. `tests\make_fake.py`로 기존 시험 세트 26건(text 8, hwpx 2, scan 8, fax 8)을 만든다. 글꼴은 `C:\Windows\Fonts\malgun.ttf`를 쓴다. 학습 실험용 새 세트 12건(N01~N12)은 `tests\make_fake2.py`로 만든다. 각 파일마다 정답표 `*.answer.json`(가려야 할 글자와 종류, 걸리면 안 되는 값)이 함께 생긴다.
2. 가짜 공문에 반드시 넣을 경우는 v1과 같다.
   - 표의 `성명 | 홍길동`, `연고자 | 김철수 (장남)`, `신고인 | 이영희`
   - 본문에 다시 나온 `홍길동 님`, 띄어 쓴 `홍 길 동`, 성을 뺀 `길동 씨`, `故 홍길동`
   - 라벨 없는 `500101-1234567`, 일부 가린 `450315-2******`, `010-1234-5678`, `(02) 123-4567`, `공일공 일이삼사 오육칠팔`
   - 라벨 없는 주소 `서울특별시 가상구 예시로 12, 101동 202호`, 지번 주소 `가상시 샘플동 123-4번지`
   - 담당 공무원 `주무관 박민수`, 기관 대표번호 `1588-0000`
   - 걸리면 안 되는 값: 문서번호 `복지정책과-12345`, 날짜 `2026-10-26`, 금액 `1,234,567원`, 사업자번호 `123-45-67890`, 일반 낱말 `이사`, `오후`, `구청`
3. `pytest tests\` — 정규식마다 맞아야 할 예와 걸리면 안 되는 예를 단위 시험으로 둔다(맥 시험 66건).
4. `python app\mask.py run --inbox tests\fake --out tests\out\win_first` — 전체 흐름을 돌린다. 시험 결과 폴더는 덮어쓰지 않고 실행마다 새 이름을 쓴다.
5. `python tests\evaluate.py tests\out\win_first`로 채점한다.
6. `python app\learn.py init-base --from tests\out\win_first --fake tests\fake`로 회귀 기준을 만든다.
7. 오답 노트 시험: 새 세트 N01~N12를 처리하고, 절반(N01·N02·N04·N05·N06)의 오답만 검수 화면에서 표시한 뒤 `learn.py ingest`를 돌린다. 나머지 절반과 기존 26건으로 학습 전후 성적을 비교한다. 수정안 승인은 직원이 한다.
8. 합격 기준:
   - 기존 시험 세트 26건에서 정답표 항목을 **하나도 놓치지 않는다**(재현율 100%). 팩스는 OCR이 읽은 범위 안에서 판정하고, OCR 단계 손실 건수를 따로 보고한다.
   - 걸리면 안 되는 값은 하나도 가리지 않는다. 그 밖의 과잉 가림은 목록으로 보고한다.
   - 누출 재검사에서 실패 0건.
   - `logs\netguard.log`가 비어 있고, 방화벽 규칙으로 바깥 연결이 실패한다(2절).
   - stdout과 `logs\`에 가짜 값이 한 번도 나오지 않는다(`tests\check_logs.py`).
   - 팩스 흉내 이미지에서 뒤집힌 장이 180도 회전으로 바로 읽힌다.
   - 오답 노트: 학습 뒤 기존 26건의 놓침과 금지값 가림이 늘지 않는다. `tests\check_fake_leak.py`가 `learn\`에서 자기 문서의 원래 값을 0건 찾는다.
9. 단체가 개인정보를 가린 견본 공문 한두 장을 주면, 그 견본(이미 가려져 있으므로 Claude Code가 읽어도 된다)으로 자주 오는 양식의 칸 목록을 만들어 `labels.yaml`의 `forms:`에 추가하고, 견본의 표 모양을 본뜬 가짜 공문을 더 만들어 4~8번을 다시 돌린다.

## 16. 단체 PC로 옮기는 방법 (새 절)

맥 시제품 코드를 묶음 파일 하나로 넘긴다. 처음부터 다시 짜는 것보다 시험을 통과한 코드에서 시작하는 편이 빠르고 안전하다.

- 묶음 파일: `nanum-mask-code-2026-10-26.zip`
- **넣은 것**: `app\`(코드, kordoc 통신 감시 장치 `netguard.cjs`, Windows 래퍼 예시 `kordoc-safe.cmd`), `config\`(라벨 사전·오탐 방지 낱말·정책 기본값), `tests\`의 시험 스크립트(`make_fake.py`, `make_fake2.py`, `evaluate.py`, `replay.py`, `test_rules.py`, `check_logs.py`, `check_fake_leak.py`, `sim_marks.py`, `run_all.sh`), `requirements.txt`, `README.md`, 이 지시서 v2. 묶음 안의 이름·번호는 시험 스크립트에 적힌 지어낸 값뿐이다
- **뺀 것**: 가짜 공문과 정답표(`tests\fake\`, `tests\fake2\`), 시험 결과(`tests\out\`, `results\`), 회귀 기준(`tests\regress\`), 맥 학습 실험의 학습 상태(`tests\learn_*`), 모델(`models\`), 가상환경(`.venv\`). 가짜 공문은 생성 스크립트로 단체 PC에서 다시 만들고, 회귀 기준은 단체 PC의 첫 시험 결과로 `init-base`를 실행해 다시 만든다. 맥에서 만든 OCR 결과는 Windows의 OCR 결과와 다를 수 있기 때문이다.
- 맥 학습 실험에서 배운 낱말(`learned.yaml`)과 승인한 정규식(`rules_extra.yaml`)은 넣지 않는다. 가짜 세트에서 배운 것이므로 실제 공문에 맞는지 알 수 없다. 단체 PC의 `learn\`은 빈 상태로 시작한다.
- 옮기는 방법: 묶음 파일을 USB 메모리나 단체 메일로 서버 PC에 옮겨 `C:\nanum-mask\`에 푼다. 묶음 안에 개인정보는 없다.
- kordoc 경로: 맥 코드는 `NANUM_KORDOC` 환경 변수가 있으면 그 경로를 kordoc 래퍼로 쓴다(`app\extract.py`, `tests\make_fake.py`). 단체 PC에서는 시스템 환경 변수 `NANUM_KORDOC=C:\nanum-mask\app\kordoc-safe.cmd`를 설정한다. 견본 생성용 글꼴은 `FAKE_FONT` 환경 변수로 준다.
- 파이썬이 `.cmd` 파일을 실행할 때 인자에 특수 문자(`&`, `|`, `%` 등)가 들어가면 cmd가 잘못 해석할 수 있다. 맥 코드는 원래 파일 이름을 그대로 kordoc에 넘긴다. 단체 PC에서는 kordoc에 넘기기 전에 `secure\work\<문서번호>.<확장자>`로 복사해 넘기도록 고친다. 이렇게 하면 특수 문자 문제와 함께 고인 이름이 든 파일 이름이 명령줄에 남는 문제도 없어진다.

Windows에 맞게 바꿀 곳:

| 위치 | 맥 | Windows |
|---|---|---|
| kordoc 실행 | `kordoc-safe.sh`(sandbox-exec + netguard.cjs) | `NANUM_KORDOC` 환경 변수로 래퍼 경로를 준다. 래퍼 `kordoc-safe.cmd`는 `KORDOC_OFFLINE=1`, `NODE_OPTIONS=--require C:\nanum-mask\app\netguard.cjs`를 설정하고 `C:\nanum-mask\node\node.exe`로 kordoc의 `cli.js`를 실행한다. 운영체제 수준 차단은 방화벽 규칙(2절)이 맡는다 |
| 경로 구분자 | `/` | 코드는 `pathlib`를 쓰므로 그대로 동작해야 한다. 시험 스크립트의 셸 명령(`run_all.sh`)은 PowerShell로 옮긴다 |
| 글꼴 | 맥 기본 한글 글꼴 | `C:\Windows\Fonts\malgun.ttf` |
| 시간 측정 | `/usr/bin/time -l` | `Measure-Command`와 작업 관리자의 최대 메모리 |
| 메모리·CPU 측정 코드 | `mask.py`가 `resource` 모듈을 쓴다 | Windows에는 이 모듈이 없다. 묶음의 `mask.py`는 모듈이 없으면 자식 프로세스 CPU와 최대 메모리를 0으로 기록하고 계속 처리한다. 측정이 필요하면 `psutil`로 바꾼다 |
| PaddleOCR 검출 모델 | mobile만 동작 | server도 시험해 비교한다(3절) |
